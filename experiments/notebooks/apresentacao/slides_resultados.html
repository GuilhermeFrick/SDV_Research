Análise Crítica · ⚠ Weighted Average

⚠ F1 = 0.97 — O que o artigo realmente reporta

O problema: F1 weighted ≠ F1 da classe ataque

O weighted average pondera cada classe pelo número de amostras. Com 88% de tráfego normal no dataset, a média é dominada pela classe normal — que o modelo aprende facilmente.

MétricaValorO que significa
F1 weighted 0.97 Dominado por 88% de amostras normais — não reflete capacidade de detecção de ataque
F1 classe normal ~0.983 Alta — modelo identifica tráfego normal com facilidade
F1 classe ataque 0.845 Esta é a métrica relevante para IDS — 0.13 abaixo do F1 weighted
Recall classe ataque 0.737 26 % dos ataques NÃO são detectados com o threshold ótimo de F1

Cálculo do weighted average

# sklearn — average='weighted'
F1_w = (F1_normal × N_normal + F1_ataque × N_ataque)
       / (N_normal + N_ataque)

     = (0.983 × 6 285 514 + 0.845 × 831 159)
       / 7 116 673

     ≈ 0.966   ← isso é o "F1 = 0.97" do artigo

Impacto operacional

Em um IDS para redes veiculares, recall de 0.737 significa que 1 em cada 4 ataques reais não gera alerta. Para segurança veicular, isso é operacionalmente crítico — especialmente em ataques MITM que comprometem mensagens de controle.

Por que o CTGAN não ajudou?

  • As 12 features comportamentais já são suficientemente discriminativas para o XGBoost — o sinal de separação é forte sem balanceamento
  • O dataset original contém representação adequada dos padrões de ataque (831 K amostras reais de ataque)
  • O CTGAN gera amostras similares às de treino, não novas — não adiciona variabilidade relevante
  • O XGBoost com scale_pos_weight ou pesos de classe seria mais simples e provavelmente equivalente

Conclusão sobre o CTGAN

O CTGAN é o componente central do pipeline proposto por Kim et al. A reprodução mostra que ele não contribui para a melhora do desempenho neste dataset, questionando sua necessidade prática e o custo de 22 minutos de GPU.

Conclusão sobre o trade-off

Nenhum threshold neste modelo resolve simultaneamente o problema de recall alto e falsos positivos baixos. O gargalo não é o algoritmo — é a quantidade de features discriminativas (12 features comportamentais), que não capturam completamente as anomalias de tipo MITM de baixa intensidade.

⚠ DT com maior recall de ataque — artefato!

O DT retorna probabilidades discretas (0 ou 1) por folha pura. Com threshold=1.0, o resultado é idêntico à predição hard do DT — que por construção maximiza pureza de classe.

O recall alto não reflete melhor discriminação probabilística. Evidência: PR-AUC = 0.708 vs XGB 0.9315. DT não é superior — é um artefato de avaliação com score discreto.

Ensemble supervisionados dominam

XGB · LGB · RF · KNN agrupam-se em:

  • Weighted F1: 0.965 – 0.966
  • Attack recall: 0.726 – 0.737
  • Diferença entre eles: marginal

O ganho de complexidade (XGB→LGB→RF) não justifica custo adicional.

Modelos não-supervisionados muito abaixo

AE (0.703) · IF (0.545) · LOF (0.236) ficam significativamente abaixo dos supervisionados — indicando que as 12 features comportamentais fornecem sinal discriminativo forte para abordagens supervisionadas simples, mas não para detecção de anomalias genérica.

✗ Três pontos não destacados no artigo

1

F1 = 0.97 é weighted average, não da classe ataque. F1 ataque real = 0.845, recall ataque = 0.737. A denominação isolada induz interpretação otimista.

2

CTGAN não contribui para a melhora. Componente central do pipeline proposto, custou 22 min de GPU e piorou levemente todas as métricas (delta = −0.0002 a −0.0015).

3

Avaliação comparativa: XGB, LGB, RF e KNN são virtualmente idênticos. DT tem maior attack recall por artefato de predição discreta. Modelos não-supervisionados ficam significativamente abaixo.

Limitação operacional central
