Estratégia de Desenvolvimento

Por que treinar classe a classe antes do multiclasse?

Cada tipo de ataque SOME/IP tem uma assinatura comportamental distinta. Treinar classificadores binários individuais primeiro permite:

  • Entender quais features discriminam cada ataque
  • Validar o labeling por conteúdo antes de combinar classes
  • Identificar sobreposições entre ataques (ex: DoS vs Fuzzy em taxa de pacotes)
  • Ter baselines individuais para comparar contra o modelo unificado

Classificador MITM — Man-in-the-Middle

Concluído com labels por conteúdo. Ambos os classificadores treinados — resultados abaixo.

MITM Multi (2 atacantes .14, .15)

3 componentes: relay via serviço falso (svc=0x100B), SD spoofing com IP forjado, e injeção ADAS.

ComponenteCritério de label
A — Event Relaysvc=0x100B + meth=0x0001
B — SD Spoof (IP forjado!)IP.src=.10 + is_sd + msg=0x02
C — ADAS Injectionsvc=0x1001 + meth=0x0001
Labeling por IP perderia os 167k pacotes do componente B (IP forjado). Labeling por conteúdo os captura.

MITM Single (1 atacante .13)

2 componentes: SD withdraw para desconectar a vítima, seguido de injeção de notificações ADAS forjadas.

ComponenteCritério de label
A — SD Withdrawis_sd + msg=0x02 + src=.13
B — ADAS Injectionsvc=0x1001 + meth=0x0001 + src=.13
Dataset: 7,2% ataques (Multi) · 8,5% (Single) — desbalanceamento moderado (11–13:1).

Desafios do multiclasse

  • DoS e Fuzzy compartilham svc=0x1001 + meth=0x0001 — diferenciados por f08 e f18
  • MITM e DoS têm f17 elevado — diferenciados por svc e f22
  • FakeClientID é furtivo: taxa e payload normais, apenas client_id rota
  • Datasets de origens diferentes (Kim vs Alkhatib) — possível distribuição shift
